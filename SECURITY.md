# Security Policy

## Supported Versions

We release security patches for the latest minor version and the previous minor
version for the last 6 months. GitStack does not maintain long-term support
(LTS) releases.

| Version | Supported |
| --- | --- |
| Latest minor | :white_check_mark: |
| Previous minor (last 6 months) | :white_check_mark: |
| Older versions | :x: |

## Reporting a Vulnerability

Please report security vulnerabilities **privately**. Do **not** open a public
issue for security problems.

**Primary channel:** send a detailed report to
[moreno.bruschi@live.it](mailto:moreno.bruschi@live.it). Include:

- A description of the vulnerability and its impact.
- Steps to reproduce (PoC code, scripts, or requests if applicable).
- Your contact information for follow-up questions.

**Secondary channel:** GitHub Private Vulnerability Reporting on the mirror
repository (`<repo-url>` → *Settings* → *Security* → *Private vulnerability
reporting*). Activation of this feature requires a board action on the GitHub
repository settings.

## Response Time

We aim to respond to security reports within **5 business days**. We will
acknowledge receipt and provide an estimated timeline for a fix.

## Public Disclosure

After a vulnerability is resolved, we will publish a public advisory describing
the issue and the affected versions. The advisory is published after the patch
is available, giving users time to update.
