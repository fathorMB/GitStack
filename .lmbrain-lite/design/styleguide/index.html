GitStack

Il tuo codice, le tue issues e domani le tue app, sui tuoi server. Un'interfaccia da console: densa, prevedibile, pronta a crescere da "mini GitHub" a "piccolo cloud privato".

Principi

Quattro regole per ogni schermata. Se una scelta di design le viola, si cambia la scelta.

1. Familiare prima che originale

Chi usa GitHub deve trovare le cose dove se le aspetta: tab Code/Issues, stati verde/magenta, #numeri.

2. Densità da strumento

Righe da 36–40 px, testo base 14 px. Più informazioni utili per schermo, senza affollare.

3. La console cresce

La barra laterale ospita già le sezioni future (App, Database, Registry): si aggiungono voci, non si ridisegna.

4. Agenti visibili

Ciò che fa un agente è sempre riconoscibile (badge agent) e tracciabile.

Marchio

Il simbolo è una pila di tre strati: il livello pieno è il codice, i due sotto sono ciò che GitStack costruirà sopra (build, app). Il nome si scrive sempre GitStack, con S maiuscola e senza spazio.

Colori

Neutri lavanda e un solo accento viola. La sfumatura Aurora (viola → magenta → arancio) è riservata al marchio: logo, voce attiva della sidebar, agenti, pagina di login. I colori di stato si usano solo per significati di stato, mai come decorazione. Ogni colore è un token: nel codice si usa sempre var(--token), mai un valore esadecimale. Cambia tema in alto a destra per vedere i valori scuri.

Icone

Icone lineari, tratto 1.8, 16 px nell'interfaccia e 20 px nella barra laterale. Nel codice useremo Lucide (licenza ISC, compatibile AGPL), che ha lo stesso stile di queste.

Bottoni

Un solo bottone primario per vista (l'azione principale). Il testo è un verbo: "Create repository", non "OK". Le azioni distruttive sono rosse solo al passaggio del mouse e chiedono sempre conferma.

Form

Etichetta sopra il campo, aiuto sotto in grigio, errore sotto in rosso che dice come rimediare. Campi alti 32 px.

Codice

Blocchi di codice con sfondo dedicato e colori di sintassi a contrasto AA in entrambi i temi. Hash, branch e comandi sempre in monospazio, con bottone copia.

// Handler returns the repository metadata.
func (h *Handler) GetRepo(w http.ResponseWriter, r *http.Request) {
    repo, err := h.store.FindRepo(r.Context(), chi.URLParam(r, "owner"), chi.URLParam(r, "name"))
    if err != nil {
        writeError(w, err, 404)
        return
    }
    writeJSON(w, repo)
}

Agenti

Gli agenti di coding sono utenti di prima classe. Quando un'azione arriva da un token di tipo agente, l'interfaccia lo dice.

build-agentagentvia token "claude-code" of mrossi · 5 min ago

Opened branch fix/ssh-ed25519 and pushed 2 commits. Tests pass locally.

  • Avatar con sfumatura arancio → magenta e icona robot, badge agent accanto al nome.
  • Sempre indicato per conto di chi agisce l'agente (il proprietario del token).
  • L'etichetta agent-ready segnala issues pronte per essere prese da un agente.

Tono di voce

L'interfaccia è in inglese di default, con traduzioni (italiano incluso) dalla prima versione. Frasi brevi, "sentence case", niente punti esclamativi.

Implementazione

Come si traduce questa guida nel codice di web/.

TemaScelta
TokenVariabili CSS in web/src/styles/tokens.css, identiche a quelle di questa pagina. Tema scuro con [data-theme="dark"] e prefers-color-scheme.
ComponentiLibreria interna in web/src/ui/ (Button, Input, Badge, Label, Tabs, List, Card, Alert, Menu, Toast, EmptyState). Base accessibile: Radix UI Primitives (MIT).
Iconelucide-react (ISC).
CodiceEvidenziazione con Shiki (MIT), temi mappati sui token --tk-*.
AccessibilitàContrasto WCAG AA, focus visibile (--focus), tutto usabile da tastiera, stato mai solo a colori.
